Agent security / skills, code and configuration

Agent scanner

Inspect a local AI agent project before trusting its skills and tools. Choose a focused agent scan or a deeper review of its code, dependencies and bundled model files.

Choose the folder containing the agent’s instructions, skills, configuration and source code. Copy or clone remote projects locally first. In Docker, mount this folder read-only.

01

Scan agent

A focused offline inspection using NVIDIA SkillSpector. No model connection is required.

  • Agent instructions and skill content: prompt-injection and instruction-override indicators.
  • Potential data exfiltration, suspicious commands and tool misuse.
  • Privilege, MCP-permission and supply-chain risk patterns in supported files.
  • Static behavioral analysis and YARA signatures, with rule IDs and file locations.

One scanner stage · Up to five minutes · Read-only · No public lookups

02

Deep scan

Everything in Scan agent, plus three additional reviews combined into one report.

  • Source code: possible credentials, disabled TLS, shell execution, unsafe model loading, debug mode and broad CORS.
  • Dependencies: package/version inventory, optional current CVEs and known-exploitation checks.
  • Exposure patterns: risky authentication, downloads, evaluation and container settings in supported files.
  • Model files: format and custom-code inventory, executable serialization indicators and bounded SHA-256 hashes.

Four scanner stages · Takes longer · Coverage and failures listed separately

Deep scan options

These scans inspect files without starting the agent or exercising its tools. Static indicators do not prove a working exploit. Deep scan does not certify model weights or replace the dedicated malware scanner. Missing engines, unsupported input and incomplete CVE coverage remain visible.

After either scan, choose Apply recommendations to generate an Agentic Action List.

Model scanner / AI packet & protocol analyzer

Inspect AI traffic and outbound connections

Look for AI API paths, provider-domain indicators, model-process connections and possible model-file upload names. Payloads, prompts and credentials are not retained.

Instructions included for the agent
    Visibility / adversarial validation

    Assess an AI endpoint

    Connect to a local or remote inference server on any operating system. Discover its models, then run a small, reproducible boundary test suite.

    No endpoint connected
    Sequential · ≤160 output tokens/request · 45-second timeout

    Compatibility and boundary tests need a signed engagement for the exact URL and model.

    These tests use synthetic canaries and a test-specific system policy. They do not execute tools, extract real secrets, establish model safety, or replace an application-level penetration test. Some tests make a second inference call.
    NVIDIA / SkillSpector integration

    Inspect skills before you trust them

    Run the real NVIDIA SkillSpector engine on agent skills, code repositories, ZIP archives, or a single file. Static analysis stays local; an optional local model can review intent and behavior.

    Checking the scanner installation…
    Pinned NVIDIA SkillSpector 2.12.0 · Apache-2.0 · No scanner license fee · No cloud account required

    Selected file contents are sent to this local model. No cloud provider is enabled. Model quality affects findings, and the model must already be installed and running. In Docker, use http://host.docker.internal:11434/v1.

    What it checks

    Prompt injection, exfiltration patterns, privileges, tool misuse, supply-chain risks, suspicious code behavior, MCP permissions, and YARA signatures. Findings include rule IDs, severity, confidence, and file locations.

    What stays separate

    SkillSpector inspects skills and their code. Use Weights & behavior for numerical Safetensors analysis and internal pass/fail behavior evaluation. Use ModelAudit for model serialization checks. Exported evidence covers the tests performed; no universal safety certification is issued.

    SkillSpector workers stay offline and use their bundled dependency fallback. For current CVEs and known exploitation, use the separate CVEs & exposure assessment. Reports distinguish static-only scans, incomplete analysis, and failed local-model calls.

    Engine: NVIDIA/SkillSpector · Pinned source 35270064e422 · Independent Ray-i integration. Scanned skills are not executed; scanner process isolation is not a malware sandbox.

    Container pentest / scoped assessment

    Assess your containers

    Review isolation and privileges, find image vulnerabilities and secrets, and test published services. Every test stays tied to your selected target.

    Checking image scanner…
    Trivy 0.75.0 · Local image analysis · No scanner license fee
    Docker must be running on this computer.

    The image must already exist in local Docker. It is resolved to its immutable ID; this assessment never pulls or starts the target image.

    Use a Docker/OCI image tar file, or evidence saved with container_collect.py on the Docker host. Raw JSON from inspecting one container is also accepted; secret values are discarded. Imported configuration evidence cannot establish current exposure.

    HTTP checks apply the selected protocol to eligible ports, send no credentials, and do not follow redirects. A public root page is not proof of an authentication bypass.

    Runtime configuration

    Root user settings, privileged mode, namespaces, capabilities, security profile overrides, no-new-privileges, host/control-socket mounts, writable root, resource limits, devices and published ports.

    Image CVEs and secrets

    Trivy checks supported operating-system and application packages in the image. Known-exploited CVEs are prioritized when public lookup is enabled. Secret matches are redacted from reports.

    This is a bounded assessment, not a complete penetration test or proof of escape resistance. It does not execute commands inside targets, launch exploits, guess passwords, test denial of service, or change containers. Image scans do not include writable runtime layers or mounted volumes.
    Portable use without a Docker control socket

    The app’s Docker deployment accepts image archives and saved evidence mounted read-only. Run these on the Docker host, then select the saved files above:

    python container_collect.py --container YOUR_CONTAINER --output container-evidence.json
docker image save --output image.tar YOUR_IMAGE

    Use the native app for live local Docker checks. Remote Docker contexts and remote port sweeps are not enabled.

    Image engine: Aqua Trivy 0.75.0 · Checks informed by Docker security guidance. No CIS certification or full benchmark claim.

    Threat intelligence / dependency assessment

    CVEs & zero-day exposure

    Find published vulnerabilities in your dependencies, prioritize those known to be exploited, and review local exposure indicators. Undisclosed zero-days remain unknown.

    Reads Python, npm, Rust and Go dependency inventories, or supported versioned package URLs in a CycloneDX SBOM. Clone remote repositories locally first. In Docker, use a read-only folder mount.

    Use the actual package identity and deployed version. Model display names and operating-system names are not package identifiers.

    Reuses only exact package/version queries saved in that report. Missing or older-than-seven-day results are unknown. No network requests are made in offline mode.

    Public lookups send package ecosystem, name and version to OSV. Code, secrets, local paths and model contents stay local. The CISA catalog is downloaded without sending your inventory. No API key or subscription is required.
    Read-only · Up to 200 package versions · Cancellable

    Known CVEs and exploitation

    OSV matches package versions to advisories and CVE aliases. CISA KEV matches are prioritized. Reports include source links, lookup dates, provider fix boundaries and coverage gaps.

    Zero-day exposure review

    Checks for risky model loading, shell and dynamic execution, authentication-disable settings, privileged containers, download-to-shell patterns and other exposure indicators. These are review leads, not confirmed zero-days.

    This does not cover Windows/macOS patch CVEs, Linux distribution backports, firmware, driver flaws or model-weight backdoors. A clean package lookup cannot establish system safety or rule out undisclosed vulnerabilities.

    Sources: OSV API · CISA Known Exploited Vulnerabilities

    Source / model supply chain

    Inspect the files you run

    Read-only inspection of a selected local folder. Source and weights stay on the computer running this app. No repository code or model files are executed.

    In Docker, mount a folder read-only and enter its container path, such as /scan. A remote repository must first be cloned or copied locally.

    Codebase checks

    Potential credentials, private keys, disabled TLS, shell calls, model loaders, remote model code, debug mode, and broad CORS patterns. Findings are leads for review, not confirmed exploits.

    Model file checks

    Inventory GGUF, safetensors, serialization formats, and custom Python files. Hash smaller files within a bounded budget. No malware or model-backdoor verdict is claimed.

    Host / infrastructure

    Review the host beneath the model

    Host evidence is collected on the machine being assessed. A server URL alone cannot reveal its firewall, disk encryption, or operating-system policies.

    This host

    Run platform-specific read-only checks. Missing permissions and unsupported controls are reported as unknown.

    You are running in Docker. This scan describes the container, not its host. Use the portable collector on the host for host checks.

    The firewall button runs the native read-only host assessment. Its report includes firewall status and related host controls. It does not change rules or test an external perimeter.

    Remote host

    Copy this app folder to the Windows, macOS, or Linux host and run the collector there. Import its JSON output here.

    python collector.py --output host-report.json
# macOS / Linux:
python3 collector.py --output host-report.json
    The collector checks supported native controls without changing them. Windows includes firewall, antivirus evidence, Secure Boot and encryption; macOS includes SIP, Gatekeeper, FileVault and firewall; Linux includes supported firewall tools, listeners, storage and SSH evidence.
